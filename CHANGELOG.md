# Changelog

Each entry states in one to three lines what the user gets, with the task id in brackets. From
1.0.0-rc.3 on the reasoning lives in `docs/` or the task report, not here; the long-form entries of
rc.3 to rc.5 and of the `Unreleased` of that time are kept verbatim in
[docs/archive/CHANGELOG-details-rc3-rc5.md](docs/archive/CHANGELOG-details-rc3-rc5.md).

## Unreleased

## 1.1.0 – 2026-10-28

The phone release: the companion flow (pick a model, slice, preview, send) works on a phone.

### Security

- **`body-parser` 2.3.0 → 2.4.0:** closes the advisory GHSA-27r3-jxmh-p828 (denial of service by trailing bytes after a compressed request body); a weekly `Dependency audit` workflow now reports new advisories.

### Added

- **The companion flow on a phone (T-091):** below 640 px the rail is a four-tab bottom bar, the
  context panel is a bottom sheet with a drag handle and the Slice button always in reach, dialogs and
  touch targets fit a thumb, and nothing scrolls sideways.
- **The 3D view by finger (T-092):** one finger orbits, two fingers zoom and pan, a tap selects, a
  double tap frames the plate, a long press offers Duplicate and Delete, and no gesture scrolls the
  page; the phone's preview frames the toolpaths per view and keeps time, filament and Send in reach.

## 1.0.0 – 2026-10-27

First stable release: the rc.6 feature set plus the fix below; the image gets the `latest` tag.

### Fixed

- **A refused address says what to change (T-090):** opening the app by a name not in `ALLOWED_HOSTS`
  (e.g. a Tailscale name) now shows a panel with the refused name, the `ALLOWED_HOSTS` line for
  Docker and Proxmox, and a link to the installation guide – instead of a dead page ([docs](docs/installation.md#opening-the-app-by-ip-host-name-or-reverse-proxy)).

## 1.0.0-rc.6 – 2026-10-26

### Added

- **A published image for plain Docker and NAS systems (T-068):** a release tag (`v*`) builds the
  linux/amd64 image and pushes it to GHCR (and Docker Hub when the maintainer configured it) only after
  a smoke test; `PUID`/`PGID` run the container with the ids a NAS uses (Unraid 99:100), the default
  stays 1000:1000, and the licence and third-party notices ship inside the image. amd64 only for now –
  arm64 users build locally (T-087).

- **Error boundary, per-token MCP quotas, audit rotation (T-081):** a component that throws shows a
  "Reload view" card instead of a blank page; a token may hold two queued jobs and 30 slices per hour;
  `data/audit.log` rotates at 10 MB and keeps five files.
- **A short Vendor profiles tab (T-076):** it opens with one summary line, lists only vendors with an
  update or in use behind **Show all vendors**, and never draws an arrow towards an older version.
- **The printer wizard asks about the hotend (T-085):** a Safety step stores the machine's own
  temperature limit per printer preset and blocks a slice above it (PTFE 240 °C) – so exporting without
  a print host is protected too; a one-time "print at your own risk" card comes before the first slice.

### Changed

- **Arranging nests the real outline (T-084):** the plater packs each instance's convex hull, keeps the
  skirt's or the brim's room at the bed edge, and can turn a part by quarter turns, so an L, an arc or
  two interlocking brackets sit closer and the arranged plate passes the plate check.
- **Plate checks on the real footprint (T-078):** off-bed, brim, skirt, overlap and the
  sequential-printing clearance measure each instance's convex hull, so rotated and interlocking parts
  slice – the same code in browser and server ([docs/safety.md](docs/safety.md)).
- **One selection rule in the object list, the scene and the Library (T-077):** a plain click picks one
  row, Ctrl/Cmd toggles, Shift takes a range, Ctrl+A selects all and Esc clears; a multi-selection gets
  group actions, and the Library gained **Load all** and **Delete selected**.
- **Cut with "keep both" places the halves apart (T-079):** the two new objects are arranged after the
  cut while the rest of the plater stays put, **Slice now** is enabled right away, and the cut plus its
  placement remain one undo step.
- **The documentation opens with an animation (T-083):** README and [docs/features.md](docs/features.md)
  start with `docs/images/hero.gif`, generated by `npm run docs:gif`; no app code changed.

### Fixed

- **A tool panel's ✕ is meant to be found, and a stale Preview says so (T-075):** every tool panel has
  a real 28 × 28 px ✕ top right ("Close (Esc)"), and a Preview result whose plate no longer passes the
  checks is drawn flat grey under an "outdated" banner instead of looking valid.

### Security

- **The settings side of the G-code preflight (T-080):** the nine custom G-code keys and the plater's
  own blocks are scanned like the output, so a binary `.bgcode` is covered; a host without a safety
  profile warns on every send; an override is refused when `data/audit.log` cannot be written.

## 1.0.0-rc.5 – 2026-10-25

### Added

- **Configuration wizard (T-061):** the Printers dialog gained a **Filaments** tab whose per-vendor
  ticks filter the filament selector, and a two-step **Custom printer** flow that creates the printer
  and its filament preset together. Both run the shared configuration limits.
- **Vendor profile updates (T-060):** the Vendor profiles tab checks PrusaSlicer-settings daily and
  installs a newer bundle per vendor with one click – validated like the bundled profiles, with a
  one-step **Revert**. `WEBSLICER_UPDATE_CHECK=off` offers **Install from file** instead.
- **Presets between installations (T-059):** a user preset can be renamed with every reference
  following; **Export presets** writes all user presets and printers as one PrusaSlicer-compatible
  `.ini`; **Import presets** reads a bundle or a G-code file's config block.

### Changed

- **Settings are where people look for them (T-074):** the **Menu** has a **Settings** group with
  **Print settings…**, **Filament settings…** and **Printer settings…**, quick settings end with **All
  settings…**, and the cog means Preferences alone.
- **The visual pass, part (b) (T-070):** the context panel reads like the mockup in all three modes –
  plate cards, the object header with **Transform**, **Settings**, **Parts** and **Layer ranges**, and a
  Preview with **Sliced info**, **Legend**, **View**, **G-code check** and **Layer** over the footer.
- **The visual pass, part (a) (T-070):** the 3D view fills the area right of the rail; the object list
  and the context panel float over it as cards, so folding or hiding them never resizes the canvas; a
  48 px top bar and the mockup's token set carry the new look.
- **The tool strip and the tool panels (L-4):** the tools are a floating pill at the top centre of the
  scene, grouped like PrusaSlicer's, with an overflow menu at narrow widths; an open tool's controls
  take over the context panel with its key hints, and `ToolDock` is gone.
- **The context panel replaces the sidebar (L-3):** a pure selector (tool > preview > object > plate)
  decides what the right column shows; the footer keeps the destination and Slice, and `Sidebar.tsx`
  is gone.
- **One home per function (L-3):** one navigation table (`web/src/nav/navMap.ts`) feeds the rail, the
  menu and the preset rows, so a function cannot grow a second door; the menu keeps import and export
  only.
- **Preferences is a real dialog:** it holds the visibility mode, the online-services status and
  **Reset panel layout**.
- **One Printers dialog (T-069):** **My printers**, **Vendor profiles**, **Filaments** and **Custom
  printer** are four tabs of one dialog, and every "Physical printers" label is gone.
- **The object list moved to the left column (L-2):** a collapsible, resizable **Object list** card
  next to the 3D view; the Preview puts **Sliced info** and **Legend** there instead.
- **New app shell with a rail and a slim top bar (L-1):** the rail holds Slicing, Library, Printers,
  Preferences and About; the top bar is one row at every width and becomes a bottom tab bar below
  640 px.
- **PrusaSlicer icons (T-063):** the tool bar, top bar, object toolbar and row actions use PrusaSlicer
  3.0's artwork from one table through `<Icon name>`, vendored by `node scripts/vendor-icons.mjs`.
- **Stable test hooks (T-062, internal):** structural elements carry `data-testid` hooks named by role,
  and the E2E suite selects them instead of by class and position. Nothing visible changes.

### Fixed

- **Leaving a tool, and a context panel that never goes empty (T-072):** move, rotate and scale only
  drive the gizmo, a click on the empty scene leaves the open tool like Esc, a tool whose object
  disappears closes itself, and the view bar is centred in the band between the cards.
- **The menu dropdown works like a menu:** one submenu at a time, opened by hover or click, with a
  grace period, Escape closing the flyout first and ↑/↓ walking the items.

### Security

- **The plate and setting checks hold on every path into a slice (T-073):** one guard in the store
  action `slice` covers both Slice buttons, the automatic re-slice and scripted calls; a stale result
  cannot be exported, saved or sent. The server refuses the same plates.

## 1.0.0-rc.4 – 2026-10-24

### Changed

- **Plater slice split (T-051):** `state/slices/plater.ts` is the composition only; the actions live in
  `objects`, `volumes`, `instances`, `transform`, `split` and `merge`, and ESLint keeps three.js inside
  `web/src/three/**`. Behaviour and undo steps are unchanged.
- **One router per resource (T-050):** `routes/api.ts` only mounts the resource routers, the logic moved
  to `server/src/services/`, `jsonStore` to `server/src/storage/`, and every JSON body goes through the
  typed `sendJson<T>` so contract drift is a compiler error.
- **One seam for every PrusaSlicer call (T-048):** the CLI argument lists live in
  `server/src/slicer/commands.ts` and are pinned by tests, and a semaphore limits all PrusaSlicer
  processes to `MAX_CLI_PROCESSES` at once.

### Fixed

- **Remaining bugs from the 2026-10-23 review (T-052):** extruder indices are clamped after a printer
  switch; concurrent REST/MCP calls no longer drop each other's objects; a cut result is discarded when
  the plater changed; history shares copy-on-write paint, and slab materials are disposed.

### Security

- **G-code preflight hardening (T-049):** the scanner understands all three Marlin line ends and
  `M 500`, records the highest hotend and bed temperature for the send gate, and knows `M121`, `M302`,
  Klipper `SAVE_CONFIG`, `M303`, chamber, RRF `G10`/`M568` and `SET_HEATER_TEMPERATURE`.

## 1.0.0-rc.3 – 2026-10-23

### Added

- **Tool framework (T-046):** a left tool bar with one panel per tool (cut, place on face, the three
  paint tools, variable layer height) from **one registry** (`web/src/tools/registry.ts`) that also
  generates the shortcut table and the About dialog.
- **Cut tool (T-044):** a plane through the selected object, cut by the PrusaSlicer CLI (`--cut`), with
  keep both/upper/lower, place on cut and flip upper part – each kept part becomes its own object and
  one Ctrl+Z restores the uncut one.
- **Variable layer height (T-045):** a continuous Z/height profile per object with Adaptive, Smooth,
  Reset and a brush, written to PrusaSlicer's own 3MF metadata and shown as a height gradient.
- **Arrange settings and "arrange selection" (T-043):** spacing, 90° rotations and block alignment,
  remembered per browser; **Shift+A** packs only the selection and treats everything else as an
  obstacle. The headless API and the MCP tool take the same options.
- **Merge, object info and rename (T-042):** two or more objects merge into one (the others become
  volumes at their world position), each row shows size, volume, triangles and open edges, and names
  are edited in place with F2.
- **STEP import (T-009):** `.step`/`.stp` files go through `POST /api/convert/step` and the normal STL
  path, so import, drop, library and the headless API all work.
- **Camera views (T-008):** **0–6** for the standard views, **K** for perspective/orthographic and **Z**
  to zoom to the selection, with one framing routine for both cameras.
- **MCP endpoint for agents, phase 1 (T-006):** Streamable HTTP at `/mcp` with token-only access,
  per-owner projects, an audit log and eleven tools; `server/scripts/mcp-e2e.ts` runs the whole
  workflow.
- **Server-side projects, MCP phase 0 (T-005):** the server builds and slices a plater without a
  browser – create, add models, arrange, slice and read a project back.
- **Preview, part 2 (T-007):** the feature legend shows time, share and extruded length per feature
  type plus travel, and a job's slicer warnings appear in a collapsible box above the statistics.
- **Preview, part 1 (T-004):** a horizontal slider plays the moves of the top layer, and every overlay
  (retractions, deretractions, seams, wipe, tool changes, colour changes, shells) toggles on its own.
- **Session restore (T-035):** a reload or a reopened browser brings the last plater back (objects,
  paint, ranges, presets, tab), with **Start empty** to clear it; a pending autosave is flushed on
  `pagehide`.
- **Unsaved-changes dialog (T-003):** switching a modified preset asks **Transfer**, **Save**,
  **Discard** or **Cancel**, listing every changed key; no browser `confirm` any more.
- **Split to objects / parts (T-002):** a multi-shell model is split with one click into separate
  objects or into volumes, with the largest part kept and one undo step each.
- **Instances (T-001):** 1–1000 copies per object, "Fill bed", the `+`/`-` keys and a size column in
  the list; one instance transform each, sliced together.
- **Mirror, duplicate and arrange** (T-001, T-002): mirrored objects keep a negative determinant in the
  project file, and arrange packs the instances themselves.
- **Layer colouring tools** (T-001, T-002): colour, pause and custom G-code at a layer, a colour-mode
  preview, the slider position kept over a re-slice and all the colour schemes with their legends.

### Changed

- **A new release is detected (T-058):** the server compares its commit with the upstream branch daily
  and the app shows a dismissible update chip and an About entry; `WEBSLICER_UPDATE_CHECK=off` stops
  every outbound request.
- **The README is a landing page (T-056):** 110 lines instead of 500, with the details in
  `docs/installation.md`, `docs/configuration.md`, `docs/mcp.md` and `docs/development.md`; the
  screenshots come from `npm run docs:screenshots`.
- **Tool bar labels and a tidier sidebar (T-055):** the tool bar names its tools while the view is at
  least 1100 px wide, with a remembered toggle, and the object toolbar no longer repeats the tools.
- **PrusaSlicer icons in the object toolbar (T-036):** real SVG icons at 18 px with a ≥ 30 px hit area,
  grouped and wrapping instead of shrinking.
- **React 19 and Vite 7 (T-027):** the only forced edit is the ref typing in `three/viewer/useScene.ts`.
- **Services layer, typed errors, async fs (R-9, T-021):** `server/src/services/` holds the use cases,
  routes only validate and answer, errors are typed and file access uses `fs/promises`.
- **One zod schema per payload (R-10, T-022):** REST and MCP share the same schemas, so a rule exists
  once.
- **Server internals split (R-11, T-028):** `layout.ts`, `threemf.ts` and `schema.ts` are split by
  responsibility with pin tests holding their output byte-identical.
- **Clean-up pass (R-12, T-029):** one `web/src/format.ts` for numbers, times and sizes, dead exports
  removed, the last store import cycle broken.
- **Express 5 (T-023):** the async handlers are plain `async` functions and the `asyncHandler` wrapper
  is deleted; every endpoint answers as before.
- **Code quality tooling (T-020):** ESLint 9, Prettier, `.editorconfig` and GitHub Actions CI running
  type check, lint, format check, tests and build on every push.
- **The E2E suite lives in the repo (T-030):** Playwright against the Docker image and a mock print
  host, sharded over three CI jobs.

### Fixed

- **Data loss and crashes (T-038):** extruder indices are clamped everywhere, undo keeps the paint, an
  `inherits` cycle is refused, cancelling works in every stage, every JSON store is written atomically
  and a corrupt file is moved aside.
- **GPU and memory resources (T-039):** geometries, materials and textures are disposed, thumbnails no
  longer read the whole G-code, the upload loop gives up after 60 s, and G2/G3 arcs are interpolated in
  the preview.
- **Maintenance quick wins (T-040, Q-006):** the audit log serves every caller, `objectIsOutside` is
  pure, the project cleanup is an explicit lifecycle hook, numeric env vars fall back with a warning,
  SIGTERM cleans up and exits, and the version comes from one source checked in CI.
- **The Proxmox helper:** when the container does not start, the real LXC error is shown; a failing
  library mount lets the install continue; the LXC template matches the host architecture; the helper
  updates an existing install.
- **Installer and helper details:** no locale warnings, a fixed service uid for bind-mounted libraries,
  and settings that survive an update.

### Security

- **Configuration limits (S1-d, S1-e):** one shared `checkConfigLimits` runs in the server before a
  slice and in the editor – blocking values redden the field and disable Slice with the reason, soft
  ranges only warn.
- **Plate validation before slicing (T-034):** a pure check over the bed polygon, brim and skirt, plus
  overlap and the sequential-printing clearance, disables Slice and names every reason.
- **G-code preflight and send gate (S1-c):** a finished file is scanned for forbidden commands,
  overwritten temperatures and moves before homing; a block refuses the upload with 409 until it is
  overridden with a reason, which is audited.
- **Send binding (S1-b):** a host linked to a printer preset only accepts a file sliced for that preset
  (or its lineage), and the override needs a reason that is written to `data/audit.log`.
- **MCP guardrails (S1-a):** `set_settings` accepts process and material options only, keeps every value
  near the resolved preset, refuses the whole call on one bad key, and audits refusals.
- **No server-side command execution (SEC-1, SEC-2):** `post_process` and `output_filename_format` are
  dropped from every merged config, and a config key must match a strict pattern at three layers; a
  Host/Origin guard (`ALLOWED_HOSTS`) closes DNS rebinding.
- **Hardening (T-037, S3–S10):** timeouts on print-host calls, pinned AppImage checksums, AGPL and
  third-party notices in the image, MCP bands that fail closed, hashed tokens, and library paths
  checked after resolving symlinks; `WEBSLICER_BRANCH` pins a release tag.
- **Uploads and 3MF bombs (T-039 S7):** uploads are streamed with the size limit enforced during the
  stream, and a 3MF is checked against its central directory (10 000 entries, 1 GiB) before inflating.

## 1.0.0-rc.1 – 2026-10-17

First release candidate for the user acceptance test.

### Slicing

- PrusaSlicer engine 2.9.6 (CLI) in the container, all print/filament/printer options of the installed version
- vendor profiles of all bundled vendors with inheritance, compatibility conditions and alias resolution
- user presets as PrusaSlicer-compatible INI, the printer's default profiles are selected automatically
- per-object settings, modifiers, support enforcers/blockers, negative volumes, additional parts
- support, seam and MMU painting; height ranges with their own layer height
- G-code with thumbnails (PNG/JPG/QOI) in filament colour

### User interface

- 3D plater with gizmo, numeric input, place on face, arrange, undo/redo, vendor bed
- settings tabs like PrusaSlicer (Simple/Advanced/Expert, search, modified markers)
- quick settings supports/infill/brim, G-code preview with layer slider and legend
- file library (mounted directory), project save/load, autosave with restore
- upload to PrusaLink, OctoPrint, Klipper/Moonraker, optionally with self-signed certificate

### Operations

- Docker image (≈ 1.2 GB) with Compose file, volumes `/data` and `/library`
- Proxmox LXC helper and Debian installer with systemd service
- sample models are copied into the library on first start
